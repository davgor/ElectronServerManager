# 042.8 — Config editor setting tooltips (Enshrouded)

Follow-up from epic **042**, requested during the 1.0 launch-day test (042.7): when editing `enshrouded_server.json` the operator cannot tell what each setting does. Show an ⓘ tooltip next to every documented key in the config editor with what it does, its default and its allowed range/options, sourced from Keen's official docs and confirmed against the config the 1.0 server actually generates. Enshrouded only for now (Palworld out of scope by operator choice).

Sources: `enshrouded_server_readme.txt` shipped with the 1.0 dedicated server (build 25936466, "Version: 1.0.0.0"), Keen's help-center "Server Gameplay Settings" / "Server Roles Configuration" articles (checked 2026-10-15; not yet updated for 1.0 settings), the 1.0 changelog, and the generated 1.0 config (which wins on disagreements: `bannedAccounts`, `randomSpawnerAmount` default `"Automatic"`, `perkUpgradeRecyclingFactor` default 0.5).

## Acceptance criteria

- [x] Docs live in the SQLite catalog (new migration, `server_setting_docs`), keyed by setting path with `*` for array entries — no game-specific branches in the renderer
- [x] Every key of a freshly generated 1.0 `enshrouded_server.json` has a doc, and no doc names a key the 1.0 config lacks (except the legacy `password`) — unit-tested against a fixture of the real 1.0 config
- [x] `gameSettings.*` docs state they only apply with `gameSettingsPreset: "Custom"`; the 1.0 additions (`flameLevelFogRemoval`, `"Automatic"` enemy amount) are described — except `flameLevelFogRemoval`, which Keen's readme lists as a server setting, so its doc makes no preset claim; every stated default is pinned to the real 1.0 config by a test
- [x] `get-server-config` returns `settingDocs` only for games that have docs; Palworld/unknown apps unchanged
- [x] Config editor shows an ⓘ (hover tooltip + accessible label) on documented top-level, nested and array-entry keys, and nothing on undocumented keys — the icon is decorative (`aria-hidden`); the doc is each control's/toggle's accessible description (not part of toggle names) and shows inline on keyboard focus (red-team fix)
- [x] README / ARCHITECTURE / ADDING_SERVERS describe the docs table; lint, type-check, tests, deadcode, build pass — 2026-10-15: all pass; full Jest 802 passed, only the pre-existing Windows `modManagerIpc` EPERM (fixed separately in PR #43) fails; diff coverage 99.0%; red-team review: no Blocking, all Should-fix items fixed
