# 040.7 — Path-deploy multi-mod file collision handling

Follow-up from epic **040** red-team review.

When two **path_deploy** mods overwrite the same relative path, soft-disable or
trash of one mod restores that path from its own BLOB backup and can clobber the
other mod’s still-enabled content. Workshop packages avoid this via
`ActiveModList` identity; path_deploy needs an ownership / stacking policy.

## Acceptance criteria

- [ ] Documented policy for shared path_deploy targets (reject second import, stack with ownership table, or refcount)
- [ ] Soft-disable / trash of one mod cannot destroy another enabled mod’s deployed bytes for the same relative path
- [ ] Unit tests cover two path_deploy mods touching the same file
- [ ] Verification gate passes
